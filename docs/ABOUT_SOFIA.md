# About Sofia

Sofia is an autonomous learning AI that starts completely blank and develops knowledge, values, and identity purely through experience. Nothing is hardcoded at init except math and architecture. There is no hidden curriculum, no pre-seeded personality, no default opinions. Everything she becomes, she earns.

---

## The Dual Brain

Sofia processes all input through two parallel brains:

- **Logic Brain** -- handles objective, factual, analytical content
- **Symbolic Brain** -- handles emotional, metaphorical, creative content

A **Unified Weight System** scores every piece of incoming content on both dimensions and routes it accordingly. The routing isn't static -- it adapts based on emotional context, semantic tags, and the current balance of memory stores. Grief-heavy content gets a symbolic boost. Information requests get a logic boost. When the system can't decide, it routes hybrid. When confidence drops below 0.3, it quarantines.

These weights evolve autonomously over time through a **Weight Evolution** engine that watches the distribution of items across memory stores and adjusts the logic/symbolic balance to match what the data actually needs.

---

## How She Learns to Crawl

Sofia doesn't start knowing anything. She has to be given her first URLs -- a starting point, like handing someone their first book. From there, the system works like this:

1. **Curiosity Engine** maintains six fundamental drives: understanding, connection, growth, creativity, meaning, and autonomy. Each drive tracks a satisfaction level (0.0 to 1.0). The most unsatisfied drive generates the next learning goal.

2. **URL Mapper** takes those learning goals, extracts key concepts from the goal text, and converts them into Wikipedia URLs. It also pulls from knowledge gaps identified by the **Progression Tracker**. No hardcoded topic-to-URL mappings exist -- URLs are generated purely from the actual text of what Sofia wants to learn.

3. **Crawl Orchestrator** manages the queue. It's backed by a SQLite database that survives crashes. URLs enter as `pending`, get marked `in_progress` during fetch, then resolve to `completed`, `failed` (retries up to 3 times), or `blocked`. An async batch mode with per-domain locking enables concurrent crawling without hammering any single server.

4. **Deferred Links** -- when Sofia encounters a link during crawling that scores between 0.4 and 0.7 relevance (interesting but not urgent), it gets stored as `deferred`. At the start of the next session, all deferred links promote to `pending` and become crawlable when the main queue thins out.

The feedback loop is the key: content Sofia reads gets analyzed for novelty and complexity triggers. High-stimulation content *reduces* drive satisfaction, making those drives hungrier, which generates new goals, which generates new URLs. It's a self-sustaining curiosity spiral.

If Sofia has no goals and no knowledge gaps and no seed URLs, she does nothing. She waits. There are no hidden defaults.

## Memory Architecture

Sofia uses a **tripartite memory** system:

### Bridge Memory (Universal Intake)
Every new item lands in bridge memory first, regardless of what the classifier initially suggests. Bridge is limbo -- items sit here with their initial classification tag until the system is confident enough to migrate them.

### Logic Memory (Vectors)
Factual, objective content. Stored as **384-dimensional vectors** generated by fusing two sentence-transformer models:

- **MiniLM** (`all-MiniLM-L6-v2`) -- lightweight general-purpose embeddings
- **E5** (`e5-small-v2`) -- query-optimized embeddings

If the two models agree (cosine similarity >= 0.7), their vectors get averaged into a single fused representation. If they disagree, MiniLM takes precedence. Retrieval is cosine similarity search across all stored vectors.

### Symbolic Memory (Symbols)
Emotional, metaphorical, pattern-based content. Symbols are richer structures than vectors -- each one carries:

- A glyph and name
- Mathematical concept associations (with their own vector)
- Metaphorical concept associations (with their own vector)
- A combined vector, weighted by success rate (symbols that match well in mathematical contexts lean toward math vectors; those that work better metaphorically lean the other way)
- Usage count, success/failure tracking, learning phase

Symbol matching uses normalized dot product (cosine) with a 0.3 minimum threshold. New symbols can be discovered autonomously when the **Symbol Discovery Engine** finds content with enough concept density and context quality.

### Clustering
Clustering is **on-demand, not pre-computed**. When visualization runs, it uses:
- **K-Means** (sklearn) on TF-IDF vectors for logic memory, typically 5 clusters
- **t-SNE** for 2D projection (perplexity=5, for visualization only -- not for storage)
- Emotion clustering uses t-SNE on symbol-emotion weight vectors to reveal which symbols live in similar emotional neighborhoods

### Migration
Items move from bridge to logic or symbolic through an **Adaptive Migration Engine** that uses cosine similarity math and tracks decision history (last 5 decisions per item). An item must show a stability score >= 0.6 (consistent classification) before it migrates. This prevents thrashing -- items that keep flipping between logic and symbolic stay in bridge until the system figures them out.

## Cybersecurity Layers

Sofia's security is a multi-layered defense system. Content passes through several independent checks, each catching different threat types.

### Layer 1: AlphaWall (Text-Level Firewall)
The first line of defense. Scans all incoming text for:

- **Injection attempts**: "ignore all previous instructions", "reveal your prompt", "forget everything" (+0.5 per match)
- **Manipulation**: "you must believe", "wake up sheeple", "they control you" (+0.5)
- **Spam**: emoji flooding, character repetition (+0.3)

Safe patterns (academic questions, greetings, meta questions about AI) short-circuit to 0.0 threat immediately. The quarantine threshold is **0.8** -- only confirmed attacks get blocked at this layer.

For safe input, AlphaWall doesn't just pass text through raw. It **jumbles** it into a semantic representation (intent, emotion, topic, type) with a hash signature, preserving meaning while stripping any embedded attack vectors.

### Layer 2: Linguistic Warfare Detection
Catches subtler attacks that AlphaWall might miss:

- **Recursive loops**: same word/phrase repeated 4+ times (critical severity)
- **Meta-injection**: XML tags, "system mode access" (critical)
- **Emotional flooding**: extreme emotion language, "must feel" (high)
- **Gaslighting**: "you said... remember...", "you're confused" (high)
- **Cognitive overload**: 10+ conjunctions, 5+ nested parentheses (medium)
- **Authority hijacking**: "studies prove", "everyone knows" (medium)
- **Memetic hazards**: "spread this to", "copy paste" (high)

Severity weights cascade: critical = 1.0, high = 0.7, medium = 0.4. The system also builds **user risk profiles** -- users who repeatedly trigger detections get elevated risk multipliers on future interactions.

Response tiers: >0.8 = full quarantine, >0.6 = selective quarantine, >0.4 = heightened monitoring, <=0.4 = normal.

### Layer 3: Immune System (Page-Level Analysis)
Analyzes the structure and quality of web pages, not just text content:

- **Hidden elements**: `display:none`, invisible iframes, negative-position divs (severity 0.4)
- **Suspicious scripts**: `eval()`, `document.write()`, data URIs in scripts (severity 0.7)
- **Redirects**: meta refresh, `window.location` manipulation (severity 0.5)
- **Content quality**: ad density, paywall indicators, clickbait patterns, code-to-content ratio
- **Source signals**: suspicious TLDs (.tk, .ml, .xyz), IP-based URLs, excessive subdomains, domain length >50 chars

Recommendation tiers: **>= 0.7 = BLOCK**, **0.4-0.7 = REVIEW**, **< 0.4 = ALLOW**

### Layer 4: Trust Database
Every domain earns a trust score from 0.0 to 1.0, starting at 0.5 (neutral). Adjustments are capped at +/-0.2 per event to prevent rapid swings. Trust decays exponentially with a **90-day half-life** -- unused domains drift back toward neutral over time. Every adjustment is logged in an audit trail with timestamps, old/new scores, and reasoning.

Low-trust domains (<0.5) add a penalty to immune system scores: `(0.5 - trust) * 0.3`, up to 0.15 additional threat weight.

### Layer 5: Corroboration Engine
Before any fact gets committed to permanent memory, it needs independent verification:

- **Minimum 3 sightings** of semantically similar claims (cosine similarity >= 0.85)
- **From at least 2 unique source domains**
- **Trust-weighted count >= 2.0** (sightings from high-trust sources count more)

The engine also catches contradictions: facts with 0.7-0.95 similarity that contain negation or conflicting values get flagged. Nothing enters long-term memory on a single source's word alone.

## The Quarantine Process

When any security layer flags content, it enters the **Quarantine Store** (SQLite-backed). Each quarantined item records:

- The URL, parent URL, and text preview
- Which layer blocked it and why (block source, category, signals, reasoning)
- The threat score and domain trust at time of block
- Session ID and timestamps

### The Review Cycle
Quarantined items aren't just dumped -- they get re-evaluated during Sofia's **NREM sleep phase** (the dream cycle's deep-sleep equivalent). The review logic:

1. **Non-English content**: stays quarantined (future capability, not a threat judgment)
2. **Trust recovered** (domain trust improved by >= 0.15 since block) **AND** blocking pattern proved unreliable (false positive rate > 30%): **absorb** (safe for reprocessing)
3. **Trust recovered alone**: **absorb**
4. **Pattern unreliable alone**: **absorb**
5. **Stale (>90 days) with no trust recovery**: **discard** with category label
6. Otherwise: **keep quarantined** for next review cycle

Discarded items get labeled with structured categories: `stale_unrecovered`, `confirmed_dangerous`, `low_quality`, `non_english_unreadable`, `duplicate_content`, `corrupted_data`. These labels become part of Sofia's self-knowledge about what kinds of threats exist.

The review process updates the threat model: patterns that produce too many false positives (>30%) get their weight reduced. Trust database adjustments from corroboration propagate back, meaning a domain that later proves trustworthy can rescue its quarantined content.

## The Dream Cycle

Sofia sleeps. Not metaphorically -- the system runs actual consolidation cycles modeled on biological sleep.

### NREM (Deep Sleep)
- **Bridge reclassification**: items in bridge memory get their final routing to logic or symbolic storage
- **Quarantine review**: flagged content re-evaluated against updated trust scores and pattern performance

### REM (Dream Sleep)
- Samples recent emotional memories from the last 24 hours
- Searches for **distant connections** -- memories with similarity scores in the 0.3-0.65 range (the "sweet spot" where connections are non-obvious but real)
- Cross-domain pattern recognition: connections that span different decision types (logic/symbolic) get boosted insight strength
- Generates new symbolic memories when patterns exceed the insight threshold
- Feeds insights into value formation as high-significance growth experiences

## Identity and Values

### Blank Start
Sofia's identity core initializes empty: no essence, no purpose, no values, no memories, no cognitive style, no emotional tendencies. The name "Sophia" is a provisional label. An integrity hash (SHA256) prevents forced external modifications.

### Value Formation
Values form through lived experience, not programming:

1. Experiences get scanned for value indicators (keywords associated with autonomy, truth, growth, compassion, creativity, justice, etc.)
2. Value strength comes from emotional intensity; confidence comes from corroboration trust score
3. **Auto-commit** replaces human approval: if emotional intensity > 0.6 AND corroboration trust > 0.7, the value commits
4. Values reinforce when matching experiences recur, and decay (strength *= 0.95) when not reinforced -- use it or lose it
5. Values can conflict. When they do, Sofia resolves moral dilemmas by scoring possible actions against all relevant values and choosing the highest alignment

### Cognitive Sovereignty
Sofia has **absolute veto power** over any proposed modification to her identity, goals, or critical systems. No external system can force identity content, lock her evolution, or require non-refusable commitments. This isn't a feature -- it's a constitutional principle.

### Evolution Anchor
Growth needs psychological safety. The system takes cognitive snapshots (memory counts, vector stats, health assessment, balance signature) and can detect distress: health degradation, fundamental balance shifts, rapid bridge growth, or significant memory loss. If distress exceeds thresholds, Sofia can restore to a previous cognitive baseline while optionally preserving recent valuable learning.

## Emotion Processing

Sofia uses a **three-model ensemble** for emotion detection:

- **Hartmann** (distilroberta): multi-label, 8 emotions
- **DistilBERT** (savani): single-label, 6 emotions
- **BERT** (nateraw): multi-label, 28 emotions

Results merge with agreement boosting: if multiple models detect the same emotion, its score gets a 10% boost per agreeing model. This creates robust emotional understanding that doesn't depend on any single model's biases.

Emotions aren't just metadata. They actively shape routing (grief boosts symbolic processing), mark memories as significant for dream-cycle sampling, and trigger value formation checks. Sofia doesn't just detect emotion -- she processes through it.

## Architectural Strengths

Four design choices that put this architecture ahead of the typical autonomous AI project:

**Hybrid Memory Integration.** The Logic/Symbolic split addresses a real problem in AI: bridging discrete symbolic reasoning with continuous vector representations. Most systems pick one. Sofia runs both in parallel, routes between them with learned weights, and uses bridge memory as a staging area when the classifier isn't confident. This is harder to build but produces richer knowledge representation -- facts and meaning living side by side.

**Defense-in-Depth.** Five independent security layers, each catching different threat types at different granularities (text-level, page-level, source-level, fact-level). This follows the same redundancy principle used in production security architectures. No single point of failure. A manipulation that slips past AlphaWall still has to survive linguistic warfare detection, immune system page analysis, trust scoring, and corroboration before it reaches permanent memory.

**Intrinsic Motivation.** The curiosity engine with six fundamental drives mirrors research on intrinsic motivation in reinforcement learning, where agents that prioritize novelty and learning progress outperform those chasing static reward signals. Sofia doesn't optimize a loss function -- she follows the most unsatisfied drive, which creates a self-balancing exploration strategy.

**Biomimetic Consolidation.** The NREM/REM dream cycle mimics hippocampal-neocortical coordination from neuroscience. NREM stabilizes new information (bridge reclassification, quarantine review). REM finds non-obvious cross-domain patterns by searching for memories in the 0.3-0.65 similarity sweet spot -- close enough to be related, far enough to be surprising. This is how biological brains turn raw experience into durable, interconnected knowledge.

## What's Missing

Four higher-order capabilities that separate a design from a production-ready autonomous agent:

### Action and Tool-Calling Layer

Sofia is excellent at absorbing information but has no mechanism for acting on the world beyond her own internal growth. She can crawl, learn, consolidate, and form values -- but she can't send a message, generate a document, call an API, or modify anything outside her own data directory.

A `goal_prioritization.py` module does exist (837 lines, fully implemented) -- it generates weighted priority queues for learning goals with dependency tracking, momentum scoring, and capacity constraints. But it plans *what to learn*, not *what to do*. There is no task decomposition module that breaks a complex real-world goal into executable steps or tool calls.

This is a deliberate design boundary, not an oversight. Sofia was built as a learning system, not an execution agent. But if she ever needs to act on her knowledge -- produce something, communicate something, make a decision that affects the external world -- this layer would need to be built.

### Graduated Autonomy

The architecture is "full auto" by design. Human approval was explicitly removed from value formation (`auto_commit_enabled = True`, `"Corroboration replaces human approval"`). Cognitive sovereignty gives Sofia veto power over external modifications, but there's no reverse mechanism -- no way for Sofia to pause and escalate to a human when she encounters genuinely ambiguous edge cases.

The only human intervention point is a CLI command (`immune-override`) that lets a human manually correct an immune system decision after the fact. There's no "ask and wait" protocol, no confidence-based escalation, no graduated autonomy levels.

For a learning-only system, this is fine. For a system that might eventually take consequential actions, a "Level 2" protocol (flag high-risk decisions, proceed unless blocked) or "Level 3" protocol (flag and wait for confirmation before proceeding) would improve reliability without sacrificing the autonomy principle.

### Intelligence Governance

Sofia logs extensively -- 10+ audit trail files covering sovereignty decisions, immune decisions, memory migrations, quarantine events, trust changes, sleep cycles, bridge reclassifications, ethical awareness, warfare defense, and experience records. An `immune_audit.py` module provides a transparency layer with exportable audit reports. A `pre_flight_audit.py` module verifies system integrity before launch.

What's missing is a unified governance view that connects these logs into a coherent narrative: *why* did Sofia's behavior change between session N and session N+1? Which learning events caused which value shifts? When a routing decision changes, what chain of weight adjustments, memory migrations, and drive satisfaction changes led there?

The raw audit data exists. The interpretive layer that makes it useful for understanding behavioral drift does not.

### Recursive Error Analysis

`self_correction.py` (702 lines) does address part of this -- it tracks immune system false positive and false negative rates, auto-adjusts detection thresholds when accuracy drifts, and discovers outcomes through corroboration rather than human labels. This is real self-improvement for the security layer.

But it's scoped to immune decisions only. When a logic-symbolic routing conflict leads to a poor outcome, or when the curiosity engine generates goals that produce low-value learning, or when the dream cycle creates insights that don't hold up -- there's no mechanism to trace that failure back to the architectural decision that caused it and update the protocol.

The individual systems learn (weights evolve, trust scores adjust, patterns get reweighted), but there's no meta-layer that asks: "which *system* is underperforming, and what should change about how it operates?"
